## 1. Чого просять

| Поле | Значення |
| --- | --- |
| Суть | Лише академічний SSO; аудит перегляду персональних даних з експортом; сторінка складу даних і строків зберігання |
| Навіщо | Обґрунтований доступ, відповідь на запити користувачів, можливість приймання в експлуатацію |
| Хто постраждає без зміни | Користувачі й академія; ST-01/ST-02 не можуть прийняти операційний пілот |

Наявна пов'язана історія **S-01**, як у story_ids CH-01; її SSO вже
відповідає листу й не оцінюється двічі. Два нові кандидати у ЛР11 §5
мають 5 та 3 SP, але не отримали S-ключів у чинному релізі через defer.
S-15 записує зміни заявки, а не перегляд персональних даних, тому не заміняє аудит.

## 2. Ціна зміни

П'ять вимірів — [impact.csv](impact.csv). Найбільше болить строк і
QA-gate: додаткові гроші не скорочують послідовну перевірку й не створюють
доступності QA. Це оцінка альтернативи, не вже затверджені вузли WBS.

| Поле | Розрахунок |
| --- | --- |
| Стеля годин | (0,25+0,5+1+0,25)×10×40 = 800 год |
| Ставка для ЛР15 | 480000/800 = 600 грн/год; не ринкова ставка й не blended ЛР16 |
| Годин дав спонсор | 48000/600 = 80 год |
| Годин просить зміна | BA16 + Dev32 + QA16 = 64 год |
| Вкладається у додатковий бюджет | Так, запас 16 год або 9600 грн |

Оцінка годин побудована декомпозицією, не множенням SP:
BA — 8 год інвентар і повноваження + 8 год правила зберігання/AC;
Dev — 16 год точки аудиту + 8 год захищений експорт + 8 год сторінка;
QA — 8 год доступ і негативні випадки + 8 год повнота/експорт/регресія.
Це модельна оцінка до реалізації; невідомі обсяг джерел і політика зберігання
можуть її збільшити. Аналоги WBS — 1.2.1/1.2.3, 1.3.2, 1.4.5.

Для what-if всі три пакети стоять послідовно перед фінальним go/no-go,
після чинного критичного входу: 16/4 + 32/8 + 16/2 = 16 робочих днів.
Критичний шлях 88→104, дата 24.02→18.03.2027 (без свят, як у ЛР7).
Це консервативне припущення про відсутність паралельного виконання;
повне перепланування потрібне до approve. Разом WBS688+64=752≤800,
але QA88+16=104>100, BA176+16=192≤200, Dev344+32=376≤400.
Тому вільний сумарний бюджет не доводить здійсненність фіксованої дати.

## 4. Рішення

| Поле | Значення |
| --- | --- |
| Рішення | defer |
| Обраний варіант | 3 |
| Обґрунтування | Додатковий бюджет покриває оцінку, але не доводить строк і доступність QA. Непогоджене вилучення S-09 порушує основу пошуку й SC-01, тому запуск без нового рішення не дозволено. |
| Хто ухвалює | ST-13, спонсор, A у A-07; ST-12 консультує обов'язковий gate |
| Що оновлено | У ЛР11 збережено CH-01 і R-01/R-08; тут оформлено impact.csv, цей запит і статус. Чинні backlog/WBS/estimates не змінені через defer. |

Defer узгоджене з історичним deferred CH-01. Це позиція PM у навчальній
сцені, не отримане зовнішнє погодження спонсора. Повторне рішення
потребує нового датованого запису, а не заміни CH-01.

## 5. Що сказати замовнику

Відкладаємо включення двох нових безпекових складових до рішення
про ресурсний план, зберігаючи заборону операційного запуску без них.
Попередня ціна — 64 години й 38400 грн, але послідовний gate додає
16 робочих днів, а QA перевищує свою стелю на 4 години.
PM до 12.11 передає спонсору ST-13 варіанти перепланування для рішення
за участю ST-12; це підготовлений текст, не підтвердження надсилання.
