Cycle time за зростанням: **19 нулів, 2, 3**.
Lead time: **17 нулів, 1, 2, 18, 18**.
Найближчий ранг застосовано до календарної різниці дат, не до середнього.

Історичний зріз 10.11 (18 робіт, останнє завершення 30.10): throughput
18/3=6,0; CT P50/P85=0/0, LT P85=2. Додано лише F-019–F-021;
попередні 18 рядків незмінні. Зменшення LT P85 з 2 до 1 спричинене
складом вибірки й позицією найближчого рангу, а не доведеним покращенням.
Зниження throughput до 4,2 також відображає розширення вікна до п'яти тижнів.

F-001–F-016 — дати з [журналу ЛР4](../lr04_kanban/README.md#3-дванадцять-карток).

їх не дублюємо через друге представлення дошки.
F-017/F-018 — аналітичні ключі наступних двох рядків за кроком 5.1,
а не створені заднім числом картки Project №1. Вони відповідають S-04/S-05
Project №2. Created 12.10, PM Start 27/28.10, повний навчальний обсяг AC
перевірений 30.10; джерело — [журнал спринтів](../lr03_sprint_simulation/sprints.md#історії-спринтів-і-їхні-дати).
Підсумковий Review 10.11 лише підтвердив ці результати. Функціональні Done
поля GitHub не підміняємо; приймання документальної моделі — за CH-06.

Нульовий CT більшості карток — наслідок календарної точності й коротких
документальних робіт, не відсутність витраченого часу. Немає підстав
штучно додати день чи blocked_days. Lead містить очікування до відбору
у спринт, а різниця перцентилів — показник за методикою, не точний
перцентиль часу очікування кожної картки. Картки різного розміру змішані:
4,2 не можна переносити на темп реалізації функцій. Показник охоплює
інтервал завершень, а не всі календарні дні до сьогодні.

F-019–F-021 — фактичні виправлення ЛР5–ЛР6 від 12–14.11.
Точні переходи наведені у ЛР4 §3. F-021 чекала через WIP 1/1
57 секунд до звільнення слота F-020; це час до Start, тому
`blocked_days=0`. Подія підтверджує застосування WIP, але не його
вплив на швидкість або репрезентативність календарних CT.

## 3. Дашборд

Чотири метрики: MT-01/MT-02 дають спонсору строк і незакриті ризики;
MT-03/MT-04 дають PM чергу та потік із потрібними діями після межі.
Пороги — внутрішні управлінські сигнали, не статистично доведені норми;
обидва спонсорські сигнали червоні, але це не автоматичне рішення про запуск.
Не включено власні DORA: без деплоїв і інцидентів застосунку їх немає.
