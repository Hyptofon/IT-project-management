## 2. Як рахувалася симуляція

| Поле | Значення |
| --- | --- |
| Фактичний інструмент | Python 3, стандартна бібліотека; код виконаний локально |
| Дата навчального прогону | 20.10.2026 |
| Кількість | 10 000 симуляцій **на кожен** із трьох наборів |
| Обсяг кожного сценарію | 220 SP, як в умові |
| Вибірка | Одне points_done з вибраної історії, рівноймовірно, з поверненням |
| Генератор | random.Random(20261020), новий екземпляр для кожного набору |
| Перцентилі | Найменше ціле число спринтів, яке покриває ≥50% / ≥85% прогонів |
| Навчальні дати релізу | Не обчислюються: історія іншої команди не є нашим календарем |

Для відтворення розрахунку виконайте наведений блок у Python 3.
Окремий файл не потрібен:

```python
import math
import random

def forecast(values, points=220, runs=10000, seed=20261020):
    if points < 0 or runs < 1000 or not values or any(v < 0 for v in values):
        raise ValueError("Invalid inputs")
    if points and not any(values):
        raise ValueError("No positive velocity: no finite forecast")
    rng = random.Random(seed)
    results = []
    for _ in range(runs):
        remaining, count = points, 0
        while remaining > 0:
            remaining -= rng.choice(values)
            count += 1
        results.append(count)
    results.sort()
    return tuple(results[math.ceil(q * runs) - 1] for q in (0.50, 0.85))

samples = {
    "all12": [21, 17, 26, 14, 23, 6, 28, 12, 22, 25, 18, 9],
    "sprints1_2": [21, 17],
    "sprints5_6": [23, 6],
}
for name, values in samples.items():
    p50, p85 = forecast(values)
    print(name, "P50", p50, "P85", p85, "width", p85 - p50)

assert forecast([10], 20) == (2, 2)
assert forecast([10], 21) == (3, 3)
assert forecast([0], 0) == (0, 0)
try:
    forecast([0, 0], 1)
    raise AssertionError("Expected refusal")
except ValueError:
    pass
print("Boundary checks: PASS")
```

Джерело масивів — **points_done**, не points_committed, з офіційного
lr09_reference_velocity.csv, спринти 1–12 у порядку файла.
Файл викладача не копіювався до власних CSV. Нуль у змішаній історії
дозволений: він витрачає один спринт, не зменшуючи залишок. Для історії
з самих нулів і додатного залишку алгоритм відмовляється давати скінченну
дату; для нульового залишку повертає 0/0.

Для власних сценаріїв застосовано формули дат з кроку 5:
весь REL-1 — кінець Sprint 1 + (P − 1) × 14 календарних днів;
залишок — кінець останнього завершеного спринта + P × 14 днів.
Результати записані у [forecast.csv](forecast.csv).

## 3. Дві дати першого релізу

Власні прогони 10.11.2026: 10 000 на сценарій, seed **20261110**,
масив points_done **[0, 7]**; новий генератор для кожного сценарію.
Повний REL-1 = 47 SP (сума final_estimate десяти історій);
прийнято 7, залишок **40 SP**. Подія безпеки CH-01 deferred,
тому додаткові 8 SP до чинного обсягу не включені.

| Сценарій | SP | P50 спринтів | P85 спринтів | P50 дата | P85 дата |
| --- | ---: | ---: | ---: | --- | --- |
| Весь REL-1 від першого спринта | 47 | 13 | 18 | 2027-04-12 | 2027-06-21 |
| Залишок після Sprint 2 | 40 | 11 | 16 | 2027-04-12 | 2027-06-21 |

Повний сценарій ретроспективний: 26.10 + (13−1)×14 = 12.04;
26.10 + (18−1)×14 = 21.06. Поточний залишок: 09.11 + 11×14 = 12.04;
09.11 + 16×14 = 21.06. Однакові дати отримано розрахунком, не копіюванням.
Відтворення: викликати функцію §2 як
`forecast([0, 7], points=47, seed=20261110)` і
`forecast([0, 7], points=40, seed=20261110)`.
P85 означає 85% прогонів цієї моделі, не 85% гарантію реального релізу.

## 4. Прогноз проти критичного шляху з ЛР7

| Джерело | Дата / різниця |
| --- | --- |
| План REL-1 roadmap.csv, 88 робочих днів | 2027-02-24 |
| Горизонт V07, 50 робочих днів без свят | 2027-01-01 |
| P85 залишку | 2027-06-21: на 117 календарних днів пізніше CPM і на 171 день пізніше горизонту |

CPM задає тривалості, послідовність і доступність ролей; Monte Carlo
повторює історичні завершені SP. Вони використовують різні моделі
ресурсів і невизначеності. ЛР7 стартує 26.10, фактичний Sprint 1 — 12.10;
цей зсув 14 днів не пояснюється продуктивністю. Вибірка 0/7 та зміна
приймання додають суттєве обмеження. Рішення — не обіцяти ранню дату,
розглянути скорочення обсягу або зміну ресурсів через change control;
не підганяти velocity до календаря. R-04/R-06 залишаються відкритими.

## 5. Чого вартий прогноз на моїх даних

Три незалежні запуски одного алгоритму, фіксований обсяг 220 SP.

| Джерело velocity | Спринтів в історії | P50 | P85 | Ширина P85 − P50 |
| --- | ---: | ---: | ---: | ---: |
| Навчальні дані, усі спринти | 12 | 12 | 14 | 2 |
| Навчальні дані, спринти 1 і 2 | 2 | 12 | 12 | 0 |
| Навчальні дані, спринти 5 і 6 | 2 | 16 | 18 | 2 |
| Мої спринти 0/7; той самий обсяг 220 SP | 2 | 63 | 72 | 9 |

У пари 21/17 вузький розкид вхідних значень дає 12/12: це не точність,
а відсутність у маленькій вибірці повільних спринтів. Пара 23/6 зберігає
різницю швидкостей і зсуває прогноз до 16/18; у фактичному прогоні її
інтервал **не вужчий**, ніж для всіх 12. Отже, важливі склад вибірки,
положення й ширина інтервалу, а не лише кількість запусків.

Перевірка без випадковості, згорткою дискретного розподілу, дала
12/14, 12/12 і 15/18. Для 23/6 ймовірність завершення за 15 спринтів
дорівнює рівно 0,5: потрібно щонайменше 8 значень 23 із 15 виборів.
Тому емпіричний P50 може бути 15 або 16; наш seed фактично дав **16**,
і його не підбирали за бажаною відповіддю. Це похибка Monte Carlo
на межі квантіля, а не підстава приховувати результат.
Більше прогонів зменшує випадковий шум, але не додає відсутніх типів
спринтів у двоточкову історію. Власна пара 0/7 дає 63/72 для тих самих 220 SP: це значно повільніша й ширша модель; 50% нульових виборів та зміна приймання обмежують її переносимість.

## 6. Що я кажу замовнику

У моделі залишилося 40 із 47 SP. Умовний прогноз дає 12 квітня 2027
за P50 та 21 червня за P85; це не обіцянка запуску. Два спринти мають
різні правила приймання, тому показуємо діапазон як навчальний розрахунок
і не видаємо його за калібровану впевненість. Зміна обсягу, оцінок або
новий завершений порівнянний спринт вимагають перерахунку. Власник — PM.

10.11 повторно виконано три навчальні прогони: 12/14, 12/12, 16/18;
чотири граничні перевірки пройдені. Власні два сценарії та порівняльний
прогін на 220 SP виконані тим самим алгоритмом. CSV звірено з сумою
оцінок і журналом; навчальні рядки не потрапили у velocity.csv.
