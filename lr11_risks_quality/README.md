## 3. Definition of Done

[dod.md](dod.md) містить **7 бінарних умов** та окремо пояснює застосовність
до PM-пакета і повної S-історії. Підрахунок завершених історій наведений там.

Вихідна точка — ЛР2, §6: AC, перевірки, відсутність критичних дефектів,
тестове середовище й QA. Для документального результату перевіряємо
сценарії, наскрізну узгодженість, версію та явне приймання.
Окремого QA, другої людини або зеленого CI не вигадуємо:
застосовуємо самоперевірку за чеклістом і локальний валідатор.
Усі AC залишені у backlog.csv. За CH-06 документальна модель перевіряє
їхню поведінку в навчальному форматі; перевірки працюючого застосунку
чи досягнення SC не заявляються. Частковий пакет не дорівнює повній історії.

## 4. Технічний борг

| Поле | Значення |
| --- | ---: |
| Записів у [techdebt.csv](techdebt.csv) | 3 |
| Оцінка повернення | 13 год |
| Стеля V07 | (0,25 + 0,50 + 1 + 0,25) × 10 × 40 = 800 год |
| Борг / стеля | 13 / 800 × 100 = 1,625% |
| pay_now / pay_later / accept | 0 / 2 / 1 |

Це борг **процесу й документації**, не список нереалізованих функцій.
D-01 — неузгоджені одиниці планування після переходу до PM-результатів;
D-02 — повторні ручні звірки одного правила в журналі, README та картках;
D-03 — ручний контроль публікації без CI. Обставини видимі у Sprint 1,
а рішення про погашення прийняті сьогодні.

Базова оцінка від 28.10: 4 год D-01 = 1 на звірку AC/SP + 1 на визначення способу приймання
+ 2 на узгодження обліку. 3 год D-02 = 1 на карту посилань + 2 на усунення
застарілих поточних повторів без правки історії. 6 год D-03 = 2 на аналіз
покриття + 3 на можливу автоматизацію + 1 на перевірку; це оцінка варіанта,
не доручення писати код. Це базові оцінки від 28.10, не timesheet і не
новий вимір залишку після часткового виконання 30.10.

D-01/D-02 заплановані до завершення Sprint 2. 30.10 частково виконано D-01:
визначено спосіб приймання та звірено шість AC; залишилась перевірка
підсумкового обліку. Для D-02 усунуто застарілий поточний текст S-02,
а правило обліку має одне основне місце у sprints.md. Закриття всього
боргу або фактично витрачені години не заявляються. У полях PM deliverable
чотирьох карток прямі commit-pinned URL замінили неповні текстові адреси;
доступність файлів і читання полів після зміни перевірені.
D-03 свідомо прийнятий: для малого портфеля
ручна перевірка кожного PR дешевша за нову службову інфраструктуру.
Якщо ручна перевірка пропустить дефект або стане регулярно пропускатися,
рішення треба переглянути. 13 год не додаються вдруге до продуктових
688 год WBS: це окремий реєстр вартості повернення боргу навчального портфеля.

Для замовника: поки одиниці обліку не узгоджені, не можна надійно назвати
дату за velocity; поки правило дублюється, кожне його уточнення потребує
кількох ручних звірок. Нереалізовані S-історії не названі «боргом».
