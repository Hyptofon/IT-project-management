## 1. Definition of Workflow

| Колонка | Картка потрапляє сюди, коли | Картка виходить звідси, коли |
| --- | --- | --- |
| Backlog | Є сталий F-ключ, реальна робота, виконавець, результат, acceptance checks і адресований артефакт; F-001 походить із ретроспективи ЛР3. | Картку обрано наступною; результат конкретний, потрібні для нього документальні входи доступні. |
| Ready | Результат має керований обсяг, перевірювані критерії й доступні входи; відсутня функція моделі не блокує її документальний аналіз. | У In progress є слот і фактично розпочато саме цю роботу; записано Start. |
| In progress | Є фактичний старт, виконавець Hyptofon і вільний слот; F-001 запущено першою. | Результат існує у нормативному файлі або diff, готовий checklist і є слот Review; інакше робота залишається тут. |
| Review | Результат можна прочитати, перевірки доступні, слот зайнятий; самоперевірка не видається за зовнішнє погодження. | Checks пройдені й дефекти усунені; якщо пакет потребує вибору політики, отримано явне рішення. Записуються докази та фактичний Done. |
| Done | Усі критерії картки виконані, результат збережений і є дата завершення. | Тільки реальний підтверджений дефект може спричинити reopening: попередні переходи збережені, поточну Done очищено, первинний Start збережено; повторний старт — за вільного слота. |

Правила застосовуються до F-карток. Готовність робіт спринта
визначає [DoR](../lr06_backlog/dor.md), історичні інтеграційні
залежності наведені в §7.

## 2. WIP-ліміти

| Колонка | Ліміт | Підстава |
| --- | :-: | --- |
| In progress | 2 | Конверт 1: 14 жовтня попередні 3 зменшено на одиницю |
| Review | 2 | Перевіряти результат до нового старту, не накопичувати неперевірені документи |

На живій дошці видимі `In progress (WIP <= 2)` і `Review (WIP <= 2)`.
Це ручна політика, не native enforcement. Окремий PM WIP Project №2 — 1/1;
його не підміняємо лімітами F-дошки.

За вичерпаного ліміту нову роботу не починаємо: завершуємо розпочату,
перевіряємо результат або усуваємо перешкоду. Blocked займає слот;
перенесення в Backlog лише для звільнення слота неприпустиме.
Очікування до Start через WIP не є зовнішнім blocked day.

**Коли ліміт спрацював: pending.** Фактичної картки, яка чекала через
заповнений ліміт, не зафіксовано. Досягнення 3/3 під час rework 12 жовтня
не доводить відкладеного старту. За реальної події записати того ж дня:
F-ключ, дату, колонку, заповнення/ліміт і зроблене замість нового старту.
Без цієї події M5 E не закритий; порожні слоти не заповнюємо штучно.
